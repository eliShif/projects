# Extension: statistical estimation with error analysis

This extension adds `sigvision/estimation.py`, a NumPy module that estimates
quantities from seeded synthetic data and reports bias, variance and RMSE against
an analytic reference. It builds on the existing FFT, Hann window, CA-CFAR and
seeded-signal code and leaves the existing modules, tests and C++ core unchanged
apart from one opt-in CLI flag.

## What was added

| Area | Implementation | Tests |
| --- | --- | --- |
| Noise-power estimation: mean-square and sample-variance estimators, Monte Carlo bias / variance / RMSE against the analytic values (`2 sigma^4 / n`, `2 sigma^4 / (n-1)`, and the `-sigma^2 / n` bias of the maximum-likelihood form) | `estimate_noise_variance`, `noise_estimator_theory`, `monte_carlo_noise_estimator` in `sigvision/estimation.py` | `NoiseEstimatorTests` in `tests/test_estimation.py` |
| CA-CFAR training-cell noise estimate: empirical false-alarm rate and the spread of the training average, using `detection.cfar_alpha` | `monte_carlo_cfar_false_alarm` | `CfarNoiseEstimateTests` |
| Sub-bin tone frequency: Hann FFT peak plus parabolic interpolation of the log power spectrum, compared with the Cramer-Rao bound for a real tone; detected tones refined through `detection.detect_tones` | `estimate_tone_frequency`, `estimate_tone_frequencies`, `tone_frequency_crb_std_hz`, `monte_carlo_tone_frequency` | `ToneFrequencyTests` |
| Constant-velocity Kalman filter on a synthetic 2-D track: position RMSE against raw measurements, NEES for consistency, a deliberately mismatched process model | `simulate_cv_track`, `kalman_cv_filter`, `nees`, `monte_carlo_tracking` | `KalmanTests` |
| Seeded experiment wired into the existing CLI | `run_estimation_suite`, `print_estimation_report`, `main`; `--estimation` flag in `sigvision/experiment.py` | `SuiteAndCliTests` |

## Requirement mapping

- Statistical estimation (R06): `sigvision/estimation.py`, tested in `tests/test_estimation.py`.
- Python and NumPy (R05), Python/C++ development (R07, R08), C++ development (R02):
  the estimation module is Python and NumPy only. The C++ core, its native tests and
  the parity checks are the existing ones (`cpp/`, `tests/test_cpp_parity.py`);
  no estimation kernel has been ported to C++.
- Complex problem solving (R03) and signal processing (R11): the existing detection,
  filtering and vision code plus the estimation experiments, all on synthetic data.
- Prototype-to-core workflow (R12): unchanged from the existing Python reference to
  C++ port with parity checks; no production or cross-team evidence is added.

## Running it

```sh
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
make build
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python -m sigvision.estimation --quick
.venv/bin/python -m sigvision.experiment --quick --require-cpp --estimation
```

`--seed N` changes the seed and `--json PATH` writes the report as JSON. The
printed figures are regenerated by each run. The section below records the latest quick estimation run. The Results section of `README.md` records an earlier, separate run (`sigvision.experiment --quick --require-cpp`).

## Latest quick estimation run

Command: `.venv/bin/python -m sigvision.estimation --quick` (exit code 0). Seeded synthetic data, small trial counts, one run. Each value is shown next to its analytic theory or Cramer-Rao reference.

- Noise variance, sigma^2 = 1, n = 16, 500 trials (measured vs theory). Mean-square: bias +0.0055 (0), variance 0.1163 (0.1250), RMSE 0.3407 (0.3536). Unbiased sample variance: bias +0.0019 (0), variance 0.1224 (0.1333), RMSE 0.3495 (0.3651). ML sample variance: bias -0.0607 (-0.0625), variance 0.1075 (0.1172), RMSE 0.3332 (0.3480). The variances are about 7-8% below theory, roughly 1.2 standard errors.
- CA-CFAR training cells, 32 cells, 5000 trials: empirical false-alarm rate 0.0118 (standard error 0.0014) against nominal 0.0100; noise-estimate relative spread 0.1808 against theory 0.1768.
- Tone frequency, n = 256, 100 trials per SNR, RMSE/CRB: 2.04 at 0 dB, 2.35 at 10 dB, 4.06 at 20 dB. The estimator is not efficient.
- Kalman filter, 40 tracks of 100 steps, tracks drawn from the filter's own model. Matched: position RMSE 3.006 against raw 7.044, mean NEES 3.99 (expected 4). Mismatched process noise: position RMSE 52.876, mean NEES 9866.95.

## Method notes and limits

- Tone-frequency bound: `var(f) >= 12 / ((2 pi)^2 * eta * N * (N^2 - 1))` in
  cycles/sample with `eta = A^2 / (2 sigma^2)`. It ignores the interaction with
  the negative-frequency image, so it is only meaningful away from DC and Nyquist
  (the experiment draws tones from the bin range `[N/8, 3N/8)`).
- Parabolic interpolation on a Hann spectrum has a small systematic bias that
  depends on the fractional bin offset, and Hann windowing widens the effective
  noise bandwidth. The estimator is therefore not efficient, and at high SNR its
  error is probably dominated by that bias. This is an untested hypothesis: the mean biases in the quick run are within sampling error of zero, and a mean over random fractional offsets can hide an offset-dependent bias. The tests only require the RMSE to sit above
  0.8 and below 10 times the bound; they do not claim efficiency.
- Kalman filter: the truth is generated from the same discrete white-noise-
  acceleration model the filter assumes, so the NEES check shows implementation
  consistency under a matched model, not robustness to real target motion. The
  mismatched-model run only shows that NEES detects a wrong process-noise setting.
- Monte Carlo figures carry sampling error. Tests use seeded runs with tolerances
  set a few standard errors wide; another NumPy version could change the exact
  random draws.
- All data is synthetic. Estimators are textbook methods, not new algorithms, and
  no claim about real sensors, video or driving data is made.
